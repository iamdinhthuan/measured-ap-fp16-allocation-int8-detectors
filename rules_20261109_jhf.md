# JHF. Jetson latency of the head-first SQNR allocations of YOLO26-l (written 2026-11-09, before any head-first engine was built on the Jetson)

Motivation: the article reports Jetson latency (Table 5, MAXN SUPER, TensorRT 10.3) for whole-head FP16 and the measured
allocations, but head-first output SQNR (post-freeze baseline, Supplementary Table S8), whose COCO AP on YOLO26-l is within
0.2 AP of the measured allocation, was not timed (stated as a limitation). JHF times it with the Table 5 protocol.

## 0. Graphs
- Head-first graphs hf_B0.1, hf_B0.15, hf_B0.2: the regexes of metrics/alloc_eval/yolo26l_int8ent/fxh_hyb_B{b}.json restored
  (qdq_restore.restore) in the hp32 Jetson base of Table 5 (base.onnx, sha256 65c7e25f...). Gate (passed before this rule was
  written): re-deriving mean_B0.1 from base.onnx reproduced the Table 5 graph byte for byte (sha256 6941ef86...), and the
  number of restored DQ inputs of each head-first graph equals the desktop evaluation (182, 277, 325). Script: jhf_export.py.

## 1. Session
- Power mode set by the author to MAXN_SUPER (the assistant never runs nvpmodel or jetson_clocks). Checked read-only before the
  first build and after the last timing (/var/lib/nvpmodel/status = pmode:0002 and cpu0 scaling_max_freq = 1728000); if
  either check fails the session is not compared with Table 5 and is reported only as a same-session comparison.
- Engines in a new directory ~/isci_orin/yolo26l_hf (nothing in ~/isci_orin/yolo26l is modified):
  - the Table 5 plan files, copied unchanged: base (INT8), fp16, headout (INT8 + F), head (whole head FP16), mean_B0.05,
    mean_B0.1, mean_B0.2;
  - newly built (trtexec --int8 --fp16, as in Table 5): hf_B0.1, hf_B0.15, hf_B0.2, and rebuilt mean_B0.1 and mean_B0.2
    (tags rb_mean_B0.1, rb_mean_B0.2) to bound the build-to-build latency spread.
- Timing: jhf_bench_gated.sh = orin_bench_gated.sh (wait for idle GPU and no foreign trtexec, 3 interleaved rounds, trtexec
  --warmUp=1000 --duration=20 --useSpinWait, median GPU compute time, VDD_IN), except that the power mode is read from
  /var/lib/nvpmodel/status instead of nvpmodel -q.

## 2. Gate J0 and reporting
- J0: every copied Table 5 engine reproduces its Table 5 latency (median of the three round medians) within 3%.
- Reported per engine: median of the three round medians, change vs. the same-session INT8 engine, mean VDD_IN, energy per
  frame, engine size. COCO AP is the desktop AP of the same selection (Supplementary Table S8), as in Table 5.
- If J0 passes (and the power-mode checks pass): the head-first rows (B = 10, 15, 20%) are added to the YOLO26-l block of
  Table 5 with their same-session latency change vs. INT8; the copied references are not re-entered (Table 5 keeps its numbers);
  the rebuilt-engine spread is reported in the Supplementary.
- If J0 fails: Table 5 is unchanged; the head-first latencies are reported in the Supplementary only, relative to the
  same-session references, with the J0 discrepancy.
- Wording: descriptive only (no test). The head-first vs. measured comparison is stated at B = 10 and 20% as a latency
  difference in ms and %, together with the rebuilt-engine spread; a difference smaller than that spread is described as
  "within the build-to-build spread". The limitation "head-first allocations were not timed" is removed only if J0 passes.
